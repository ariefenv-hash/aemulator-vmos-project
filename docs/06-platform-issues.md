# 06 - 平台问题记录与规避策略

> 第 7-8 轮确认的三个平台侧问题。均非工程代码问题，记录在案以免新会话误判。

## 1. 问题一：沙盒重置导致文件全丢（根因级）

- 现象：会话结束后平台回收/重置沙盒，`/home/z/my-project` 与 `/tmp` 全部清空（第 8 轮开工时实测确认：upload/ 仅剩 64KB 平台模板，分析产物/构建产物/ROM 解密产物全部消失）。
- 影响：用户"下载不到文件"的直接根因——**文件已不存在**，下载通道只是症状。
- 规避（强制执行）：
  1. 一切阶段性产物**立即** commit + push 到本仓库（代码/文档）或以 Release 资产上传（二进制）；
  2. `/tmp` 视为易失区，只放可重derive的中间件；
  3. 长任务结束时把"产物 + 生成脚本"成对入库，脚本在产物丢失时可重跑。

## 2. 问题二：预览窗口被"文件阅览"自动占用

- 现象：平台自动打开文件预览，占用了原本属于前端项目（Next.js 中控板）的预览窗口位，用户看不到中控板。
- 规避：
  1. 用户侧已改用 GitHub 仓库地址接力，中控板依赖度下降；
  2. 新会话重建工作台时，把关键交付（APK/报告/补丁）同时发布到本仓库 Release，用户直接从 GitHub 下载，绕开平台下载通道；
  3. 若仍需预览窗口，重建后引导用户手动刷新/重开预览（平台侧行为无法由会话内代码修复）。

## 3. 问题三：平台下载通道不可达

- 现象：工作目录内文件用户无法下载（第 7 轮起）。
- 根因同问题一（文件丢失）叠加通道故障；修复靠问题一规避策略 + GitHub Release 分发。

## 4. 令牌安全（本仓库自身）

- 本仓库由用户在对话中明文提供的临时 fine-grained PAT 创建并推送。
- 推送完成后**用户应立即到 GitHub → Settings → Developer settings → Fine-grained tokens 吊销该令牌**。
- 仓库内不含令牌/凭据；`.env`（仅平台本地 DATABASE_URL）未入库。
- 若后续需要继续自动推送，建议用户单独发一枚仅限本仓库 Contents(读/写) 的细粒度短效令牌。

## 5. 环境备忘（新会话必读）

- GitHub 直连（raw/api 域名）时常受阻：用 `ghfast.top` 镜像前缀加速克隆/拉取（历史实测约 30 倍）。
- 磁盘：开工时约 8GB 余量；大中间产物（解包 rom.img、反编译树）用完即删。
- 工具链：jadx 1.5.6、apktool 3.0.3、JDK 21、Python3、bun/Node 22。
- 用户时区 Asia/Shanghai；对话与文档语言：中文。
